# Работа над mattergram

## Быстрый вход

1. Прочитай README.md и STATUS.md.
2. Для задачи выбери нужные разделы docs/aiogram_mattermost_fork_spec.md.
3. Для переноса используй docs/IMPLEMENTATION_PLAN.md.
4. Для документации используй docs/DOCUMENTATION_PLAN.md.

Не загружай весь дизайн и все upstream исходники в контекст каждого небольшого изменения. Сначала используй rg для поиска символов и зависимостей, затем читай связанные файлы.

## Приоритеты

- Корректная семантика Mattermost.
- Узнаваемый интерфейс aiogram там, где есть реальное соответствие.
- Полнота нативных возможностей Mattermost.
- Повторное использование готового ядра и поведенческих тестов.
- Минимальный объём ручной генерации кода.

Не добавляй отсутствующие Telegram-функции, фиктивные ID, молчаливые no-op или административный fallback в runtime.

## Перенос

Неизменяемые upstream snapshots и новый пакет разделяются. Перенос выполняется по allowlist manifest с зафиксированными commits и лицензиями. Скрипты из плана сначала нужно реализовать; их существование не подразумевается.

Механические изменения делай скриптом/codemod. Семантические изменения делай малыми патчами с проверкой связанного поведения.

Не расширяй allowlist автоматически до всего графа Telegram-моделей ради успешного импорта.

## Проверки и отчёт

Проверяй затронутое поведение, типы и примеры. Не заменяй проверку реального протокола пустыми заглушками. Не объявляй стенд или пример проверенным, если он не запускался.

После завершённой задачи обнови STATUS.md: результат, проверки и следующий конкретный шаг. Не переписывай все документы при каждом изменении.
